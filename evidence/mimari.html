TaskFlow – Mimari ve Veri Modeli

Kaynak: app.py, schema.sql (Issue #6)

1. Katmanlı mimari

Sunum Katmanı – Jinja2 şablonları: login.html · board.html · task.html · new_task.html · reports.html (base.html + static/style.css)
▼
İş Mantığı Katmanı – Flask route'ları (app.py): Kimlik doğrulama (before_request, @roles) · İş akışı (TRANSITIONS, allowed_moves, move) · Defect yönetimi (add_defect) · Raporlama (reports)
▼
Veri Erişim Katmanı – sqlite3 (db(), init_db(), PRAGMA foreign_keys=ON)
▼
Veritabanı – SQLite (jira-demo.db, schema.sql)

2. Veri modeli (tablolar)

users

id PK
username UNIQUE
full_name
password_hash
role (admin|developer|qa)

tasks

id PK
title, description
priority, status
assignee_id → users.id
creator_id → users.id
created_at, updated_at, live_at

defects

id PK
task_id → tasks.id
title, description
severity
status (Open|Fixed|Closed)
reporter_id → users.id
created_at, fixed_at

history

id PK
task_id → tasks.id
user_id → users.id
from_status, to_status
note, created_at
İlişkiler: users 1—N tasks (atanan/oluşturan) · tasks 1—N defects · tasks 1—N history · users 1—N defects (raporlayan) · users 1—N history
